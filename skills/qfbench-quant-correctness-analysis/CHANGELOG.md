# Revision history

## 4.1 — 2026-11-15

- Added a general task-review route that works without an existing candidate, reward, benchmark identity or harness.
- Made task quality explicit: purpose and quantitative substance, validity, assumptions, well-posedness, data integrity, clarity, meaningful outputs, numerics, feasibility and fair/discriminative evaluation.
- Added a separate version 1.0 task-review report with evidence, attribution, repair status, coverage, three-round status and bounded conclusions.
- Distinguished confirmed unfixed defects, genuine evidence gaps, unverified historical claims and optional enhancements; required corrections remain minimal without reducing checks.
- Extended the agreed three-round method to full task acceptance while retaining proportionate focused diagnostics and the local/no-paid-API policy.
- Updated entry points, UI metadata and operations. Trial schema 4.0, ten mode identifiers and Python scripts are unchanged. Changed policy hashes require refreshed trial review requests.

## 4.0.1 — 2026-11-15

- Rechecked all 33 cited queue tasks, seven constructed illustrations and five retired worked examples (36 distinct task identities in total).
- Corrected overbroad citations, separated historical and repaired behavior, and documented source/provenance limits.
- Added an example-audit reference and a requirement to verify the actual version and executed cause before reusing an example.
- Schema remains 4.0; scripts and historical assessments are unchanged. New evidence is targeted source/math/grader review, not fresh blind solver benchmarking.

## 4.0 — 2026-11-15

- Kept the ten top-level mode identifiers and the skill's focus on trial-level quantitative diagnosis.
- Added suspicious-pass review and explicit cohort selection; native outcome no longer determines analytical correctness.
- Replaced asymmetric task-side rejection rules, universal convention shortcuts and fixed cascade priorities with evidence-based attribution and causal grouping.
- Added explicit insufficient/unassessed states, version-bound manual imports, separate review decisions and honest aggregation denominators.
- Made local preparation/import the default; separate provider calls require explicit opt-in and bounded configuration in addition to user authorization.
- Corrected financial guidance and condensed repeated anecdotes, release narratives and unverified calibration claims.
- Incorporated lessons from the 86-task review campaign and its superseding 13-task recheck, with explicit limits on what was executed or formally proved.

Compatibility is a deliberate major change: prior labels.json and historical calibration remain historical. Read [references/output-schema.md](references/output-schema.md) before comparing or importing labels. Earlier package contents are preserved in the update's original-skill archive rather than loaded as current instructions.
