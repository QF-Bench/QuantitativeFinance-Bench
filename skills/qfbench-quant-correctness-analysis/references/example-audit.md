# Task examples: source and claim audit

Audited 2026-11-15. This ledger covers all 33 numbered task references in the preceding skill revision, the seven constructed illustrations, and all five worked examples in the original installed package. Two legacy examples overlap the numbered set; three add task identities, giving 36 distinct tasks. The added IPCA case is queue #10; GARCH S&P 500 and ML credit scoring are outside the selected 86.

## Version and evidence limits

The numbered tasks were checked against baseline `d2fc28b3492f2d73d192fa7eabadf150a19a62fb` and local repaired snapshot `fd2fedc412c0cedb1f5a7b9ee8d8cdfab09c296c`. Table links identify the public baseline, not the unpublished repaired snapshot. “Repaired” refers only to that local version. Source hashes, actual commands, native results and controls are in the accompanying example-recheck evidence package.

Reviewers reopened relevant instructions, executable references and graders. Fresh independent calculations and targeted native-checker controls ran locally; task code ran in network-disabled Docker. Pure source parsing and some independent standard-library arithmetic ran on the host. Historical protocol failures were inspected as records, not recreated. These checks do not constitute fresh blind solver attempts, a new 86-task benchmark, formal certification or full acceptance of every task.

## Reusing a case

State the immutable task version, inspected artifact, precise disputed requirement, executed mechanism and consequence. Separate real submissions from injected controls and historical observations from fresh runs. Reopen source-dependent claims when the task changes. When the exact old trajectory or delivered instruction is missing, keep that historical attribution unverified rather than replacing it with current main or a condensed anecdote.
